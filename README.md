# Nichi Phrase Server — Claude API로 매일 새 문장 생성

정적 파일 버전과 다르게, 이 버전은 **실제로 매일 Claude API를 호출해 그날 처음 보는 10개 문장을 생성**합니다.
지금까지 생성된 모든 문장을 기록해두고, 다음 생성 요청 때마다 "이미 나온 문장 목록"을 Claude에게 함께 전달해서
같은 문장이나 비슷한 표현이 다시 나오지 않도록 합니다.

## 1. 준비물

- Node.js 18 이상 (터미널에서 `node -v` 로 확인)
- Anthropic API 키 (https://console.anthropic.com 에서 발급)

## 2. 설치

```bash
cd nichi-phrase-server
npm install
cp .env.example .env
```

`.env` 파일을 열어서 발급받은 키를 넣어주세요.

```
ANTHROPIC_API_KEY=sk-ant-여기에-실제-키
CLAUDE_MODEL=claude-sonnet-5
PORT=3000
```

## 3. 실행

```bash
npm start
```

터미널에 아래처럼 뜨면 정상입니다.

```
✅ Nichi Phrase 서버 실행 중: http://localhost:3000
```

브라우저에서 `http://localhost:3000` 을 열어보세요.

## 4. 동작 방식

1. 브라우저가 `/api/today` 를 호출합니다.
2. 서버는 `data/db.json` 에 **오늘 날짜의 배치가 이미 있는지** 확인합니다.
   - 있으면 → 그대로 반환 (API 재호출 없음, 하루 한 번만 생성)
   - 없으면 → Claude API를 호출해 새 문장 10개를 생성하고 저장한 뒤 반환
3. 문장을 생성할 때 **지금까지 나온 모든 문장 목록**을 프롬프트에 "제외 목록"으로 함께 보내서 중복을 방지합니다.
4. 혹시 그래도 겹치는 문장이 섞여 오면 서버가 한 번 더 걸러내고, 부족한 개수만큼 추가로 1회 재요청합니다.
5. 진행 상태(완료/폐기)와 생성된 모든 문장 기록은 `data/db.json` 파일에 저장됩니다. 서버를 껐다 켜도 유지됩니다.

## 5. 언제 새 문장이 생성되나요?

**서버를 켜둔 채 하루 종일 대기시킬 필요는 없습니다.** 스케줄러 없이, 첫 번째 방문(요청) 시점에
"오늘 배치가 아직 없으면 그때 생성"하는 **지연 생성(lazy generation)** 방식이라 컴퓨터를 매일 켜두지 않아도 됩니다.
날짜가 바뀐 뒤 처음 페이지를 열 때 자동으로 그날의 새 문장이 만들어집니다.

## 6. 테스트용 "다음 날" 버튼

실제로 하루를 기다리지 않고 로직을 확인해볼 수 있도록, 화면 하단에 **"데모: 다음 날 문장 새로 생성"** 버튼을 넣어뒀습니다.
누를 때마다 Claude API가 실제로 1회 호출되어 비용이 발생하니, 실사용 배포 시에는 이 버튼과 `/api/dev/advance-date`
라우트를 지우는 것을 권장합니다.

## 7. 비용 관련 참고

한 번 생성 요청마다 문장 10개(짧은 JSON) 정도의 출력이라 토큰 사용량이 크지 않습니다. 다만 실제 비용은 사용하는
모델과 Anthropic의 최신 요금 정책에 따라 달라지므로, https://console.anthropic.com 의 사용량/요금 페이지에서
직접 확인하시는 걸 권장합니다.

## 8. 폴더 구조

```
nichi-phrase-server/
  server.js              # Express 서버, API 라우트
  lib/generateSentences.js  # Claude API 호출 & 파싱 로직
  public/index.html      # 프론트엔드 (단일 파일, API에서 데이터 fetch)
  data/db.json            # 실행 시 자동 생성되는 로컬 저장소 (문장 기록 + 진행 상태)
  .env.example            # 환경변수 템플릿
```

## 9. 다음에 고려해볼 만한 것

- 여러 사용자를 지원하려면 `db.json`을 사용자별 파일/DB로 분리해야 합니다 (지금은 단일 사용자 전용).
- 진짜 배포(항상 켜진 서버)를 원한다면 자정에 미리 생성해두는 cron(예: `node-cron`)을 추가해, 사용자가 접속하는
  순간 로딩 대기 없이 바로 볼 수 있게 만들 수 있습니다.
- 생성 실패(네트워크 오류, 키 만료 등) 시 재시도 정책을 더 정교하게 다듬을 수 있습니다.
